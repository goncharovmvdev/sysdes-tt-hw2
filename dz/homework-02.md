**З** — задания, **Н** — найм, **Б** — бонусы. Границы сервисов сохраняются. «После 1» — восстановленная основа невыполненной ДЗ 1; «после 2» — план без внедрения.

## 1. Модель данных

[Исходная модель с ошибками](diagrams/01-errors.drawio) · [Исправленная модель](diagrams/02-data.drawio)

| Ошибка | Исправление | Основание |
| --- | --- | --- |
| E1. Менеджеры без источника данных | Владелец З, копия Б; профиль в Н удалить | З выбирает менеджера переделки; 010 лишняя, 070 — репликация |
| E2. Нет последнего редактора | Обновлять `reward_manager_id` при правке | Бонус получает редактор, US-112; переделку может выполнять любой менеджер, US-031/032 |
| E3. Счётчики в З, рейтинг через посредника | Попытки, статистика и рейтинг — в Н; читать напрямую по 060 | Н проверяет решения, US-080/100/111 |
| E4. Статус выполнения у задания | Статус — у назначения кандидату, результат — у попытки | Кандидаты имеют разные результаты, US-070–090 |
| E5. Рейтинг напрямую связан с балансом | Баланс — сумма операций; рейтинг сохраняется в операции | Нужны начисления, списания и выплаты, US-110–152 |

Назначение связывает кандидата с заданием; выполнением владеет Н. ID глобальные и стабильные. На схемах: числа — COMM, `1:N`/`N:1`/`1:1` — кратность, RM — read model.

## 2. HTTP и события для двух сущностей

| Сущность | Синхронно | Асинхронно |
| --- | --- | --- |
| Менеджер | `GET /api/managers/{manager_id}` | `ManagerCreated`, `ManagerUpdated` |
| Кандидат | `GET /api/candidates/{candidate_id}` | `CandidateCreated`, `CandidateUpdated` |

Выбран событийный вариант: state-снимок с ID, именем, версией; у кандидата также статус квалификации.

## 3. Связи и консистентность

[Общая карта](diagrams/03-communications.drawio). Стрелки — данные/факты; HTTP-запрос обратно. COMM-100 передаёт факт и состояние назначения одним сообщением.

| COMM | Исходно | После 1 | План после 2 / консистентность | Problem / причина |
| --- | --- | --- | --- | --- |
| 010 | HTTP: менеджер для Н | Удалена | Удалена | 060, 080, 090: менеджера выбирает З |
| 020 | HTTP: задание | HTTP | HTTP, **strong** | 020/021: актуальная версия задания |
| 030 | HTTP: назначить переделку | Факт 10 успехов | Событие, **eventual** | 010, 050, 080: Н не ждёт назначения |
| 040 | HTTP: начислить бонус | Факт успеха | Событие, **eventual**; расчёт через 060/110 | 010, 040, 050, 080: проверка не ждёт начисления |
| 050 | HTTP: списать бонус | Факт неуспеха | Событие, **eventual**; менеджер через 110 | 010, 040, 050, 080: списание вне запроса; рейтинг не нужен |
| 060 | Kafka: `TaskRating` | `TaskRatingUpdated` | **Kafka → HTTP, strong** | 030: актуальный рейтинг, US-111 |
| 070 | HTTP: менеджер для Б | HTTP | **HTTP → Kafka, eventual** | 060, 080: локальный профиль |
| 080 | HTTP: бонус за создание | Факт создания | Событие, **eventual**; расчёт через 060/110 | 040, 050, 080: создание не ждёт Б |
| 090 | HTTP: список кандидатов | HTTP | **HTTP → Kafka, eventual** | 080, 090: локальный список |
| 100 | Не выделена | Факт назначения | Событие, **eventual** | Доступ после назначения, US-070/071 |
| 110 | Не выделена | Не выделена | HTTP, **strong** | Текущий ответственный менеджер, US-112 |

**Strong:** 020 — согласовать версию задания с фиксацией проверки; 060/110 — рейтинг и редактор неизменны от чтения до записи начисления. Один HTTP недостаточен; недоступный владелец задерживает начисление.

Зависимость от актуального задания сохраняется. Problem-070, 100/101 требуют дедупликации, надёжной доставки и повторов — это следующий этап.

Внешние API: EXT-010 З→SaaS; EXT-020 Н→HCB; EXT-030 Б→платежи. HTTP для EXT-020/030 — допущение.

## 4. Топики

| Топик | События → связи | Почему вместе | Почему так назван |
| --- | --- | --- | --- |
| `data_replication.managers` | `ManagerCreated`, `ManagerUpdated` → 070 | Одна сущность | Репликация менеджеров |
| `data_replication.candidates` | `CandidateCreated`, `CandidateUpdated` → 090 | Один жизненный цикл | Репликация кандидатов |
| `domain.task_management` | `TaskCreated` → 080, EXT-010; `TaskUpdated` → EXT-010; `CandidateTasksAssigned` → 100 | Один контекст | Управление заданиями |
| `domain.teacher_hiring` | `TaskSuccessStreakReached` → 030; `TaskAttemptSucceeded` → 040; `TaskAttemptFailed` → 050; `CandidateQualified` → EXT-020 | Один контекст | Найм учителей |

При перекосе частот события разнести. Для HTTP топиков нет; поток рейтинга удалён. Формат — JSON; ID сообщения и финансового основания различаются.

## 5. Репликация или read model

| Данные | Выбор и причина |
| --- | --- |
| Менеджер, кандидат, назначение | Репликация: нужно текущее состояние |
| Задание, ответственный менеджер | HTTP у владельца: строгая актуальность |
| Рейтинг, серия успехов | Read model в Н: успехи / все попытки с округлением до 0.1; серия зависит от порядка |
| Баланс | Read model в Б: начисления, списания, выплаты |

Read model — проекция истории. До первой попытки принят рейтинг 0.
